Validations needed:

- Ignore includes for now!

- verify i/o datatypes. Only a few valid options:
    - none
    - boolean
    - number
    - string
    - number_array
    - string_array
    - color
    - sound
    - image
    - any
- Should sum types be allowed? e.g. `string|number`... Not for now.

- Each i/o datatype can only have specific constraints.
    - none
        - cannot have ANY constraints
    - boolean
        - cannot have ANY constraints
    - number
        - integer or float
        - min (inclusive)
        - max (inclusive)
        - decoration (time fmt, num decimals, etc)
    - string
        - no constraints other than type?
    - number_array
        - no constraints other than type?
    - string_array
        - no constraints other than type?
    - color
        - no constraints other than type-inherent.
    - sound
        - no constraints
    - image
        - no constraints
    - any
        - no constraints


- inputs/outputs cannot have the same name!

- only `!tick` and `!init` events are supported currently.

- no duplicate node names!

- includes
    - in-node includes can only contain *supported* source files (e.g. `.cpp`/`.hpp` or `.lua`, depending on how we go with this).
    - redundant in-node includes *in the same node* are an error.
    - redundant in-node includes *in separate nodes* are ok, and should map to the same memory location, src block etc. to save on space.

- Lua source needs to compile correctly!

- tags:
    - if tag has a parent, the parent tag must exist!
    - no circular parent routes! e.g. `@1 in @2 ... @2 in @1` is not allowed.
    - when node is tagged, make sure tag exists (maybe only warn about missing tag?)
    - no duplicate tags!
